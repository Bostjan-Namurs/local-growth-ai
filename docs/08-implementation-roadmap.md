# 08 — Implementation Roadmap

## Phase 0: Confirm assumptions

Decisions to confirm before coding:

- backend framework: Fastify,
- worker framework: BullMQ initially, Temporal later only if needed,
- frontend: Next.js,
- deployment style: Helm/Kustomize/Fleet,
- local LLM gateway: LiteLLM or custom,
- first verticals: restaurants + salons,
- first geography,
- lead source policy,
- Supabase stays external or moves into Rancher.

## Phase 1: Repo and database foundation

Deliverables:

- monorepo structure,
- backend health endpoint,
- database migration,
- Supabase connection,
- base tables,
- audit logs,
- source records,
- approval records.

Acceptance criteria:

- migrations apply cleanly,
- API health works,
- database tests pass,
- source records can be created and listed.

## Phase 2: LLM gateway integration

Deliverables:

- model alias config,
- OpenAI-compatible client wrapper,
- fake LLM test client,
- request logging,
- agent run logging.

Acceptance criteria:

- backend can call `classifier` alias,
- worker can call `writer` alias,
- agent run logs include model alias and timing,
- fake LLM tests run without real models.

## Phase 3: Lead and website audit

Deliverables:

- manual lead import,
- source compliance check,
- deduplication,
- website audit worker,
- opportunity score.

Acceptance criteria:

- manually imported lead creates source record,
- disallowed source blocks workflow,
- website audit creates audit record,
- opportunity score visible in API.

## Phase 4: CGP and proposal agents

Deliverables:

- BusinessProfileAgent,
- BlueprintMatcherAgent,
- ProposalAgent,
- approval workflow,
- admin UI lead detail.

Acceptance criteria:

- CGP generated with missing data fields,
- proposal generated from approved CGP,
- admin can approve/reject proposal,
- agent outputs are schema validated.

## Phase 5: Template app generator

Deliverables:

- restaurant blueprint,
- salon blueprint,
- app spec generation,
- content generation,
- config schema validation,
- preview build stub.

Acceptance criteria:

- approved proposal generates app spec,
- content placeholders appear for missing data,
- invalid config fails validation,
- preview URL or preview artifact record created.

## Phase 6: Rancher deployment integration

Deliverables:

- Kubernetes manifests/Helm chart,
- preview namespace deployment,
- production deployment approval gate,
- rollback metadata.

Acceptance criteria:

- preview deployment works in staging,
- production deploy endpoint refuses without approval,
- deployment metadata stored,
- rollback process documented.

## Phase 7: Campaign generator

Deliverables:

- campaign draft generator,
- campaign approval status,
- suppression list,
- manual send/export flow.

Acceptance criteria:

- campaign draft generated by vertical,
- campaign cannot send without approval,
- opted-out contacts are blocked,
- admin can export/send manually.

## Phase 8: Production hardening

Deliverables:

- observability,
- backups,
- RBAC,
- network policies,
- secrets management,
- model registry,
- prompt versioning,
- CI/CD.

Acceptance criteria:

- disaster restore tested,
- LLM endpoint private,
- admin roles enforced,
- all risky actions audited.

## First 10 Codex tasks

1. Bootstrap monorepo.
2. Add database migration from `examples/db/001_initial_schema.sql`.
3. Implement backend health and database connection.
4. Implement business/source CRUD.
5. Implement approval model and endpoints.
6. Implement LLM gateway client with fake test mode.
7. Implement `AgentProtocol` and `AgentRunLogger`.
8. Implement `SourceComplianceAgent`.
9. Implement `BusinessProfileAgent` with schema validation.
10. Implement admin lead detail skeleton.
